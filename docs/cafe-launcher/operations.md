# 游戏操作 <span id="game-operations"></span> {#游戏操作}

主窗口根据安装与版本状态显示“安装游戏”“更新游戏”或“开始游戏”。左侧悬浮游戏栏提供游戏切换、后台任务返回和设置入口，左下显示当前游戏名称。右下操作卡保持底边固定，安装、任务和错误时加宽，任务详情可展开；内容过长时可在卡片内滚动。失败持续显示在卡片中，提供适用的重试与“查看日志”，另一游戏失败可从左栏返回。右上资讯卡统一横幅、每类前三条公告及展开／收起和社交链接；小窗口或任务详情占用较多空间时收起横幅与公告，资讯列表仍可访问，游戏操作不受资讯加载失败影响。

先在游戏栏选择蔚蓝档案日服或星塔旅人国服。安装状态、公告、运行环境和游戏操作都跟随该条目；切换页面不会取消另一游戏的任务。后台任务摘要显示所属游戏，可点击返回其进度。完成与失败通知也标明所属游戏。

全局同一时间只能有一项安装、更新、修复或卸载，暂停仍占用任务位，点击“停止”后也要等清理和刷新结束才能发起下一项。受阻操作立即提示，不会自动排队。确认框打开前不占任务位，确认后会重新检查；未保存设置或模态对话框未关闭时不能切换条目。

## 安装与更新 <span id="install-and-update"></span> {#安装与更新}

1. 点击所选条目的“安装游戏”或“更新游戏”；首次安装先确认该游戏的目录，再获取清单并计算需要下载的文件。
2. 等待下载，文件先写入 .tmp，支持续传时复用已有进度。
3. 文件经过 CRC64 校验后，更新本地清单与游戏配置。

取消首次安装的目录选择不会开始下载，也不会改写任一游戏的已保存配置。已有安装可从“游戏设置 → 安装与维护 → 选择已安装游戏”识别。

![下载进度](../assets/screenshots/download-progress.webp)

进度区显示百分比、速度、大小和预计剩余时间，状态区显示当前下载源。

| 动作 | 结果 |
| --- | --- |
| 暂停 | 暂停传输，保留本次进度 |
| 继续 | 继续当前任务并复用可用临时文件 |
| 停止 | 经确认取消操作，放弃这次任务的恢复记录 |
| 正常退出 | 等待任务收尾并保留恢复记录，下次启动核对后恢复 |
| 限速 | 在[下载与网络设置](/cafe-launcher/settings#下载与网络)调整 |

主动点击“停止”会清除本次恢复记录；真正退出则保留。恢复要求游戏版本、清单、目录和下载源一致；不匹配时不会把旧任务套到新安装上。

恢复记录分别绑定游戏。正常启动只尝试恢复上次查看的条目；其他条目可切回后点击安装或更新，重新校验并复用已有文件。正常退出会等待所有游戏任务收尾，主动停止只放弃对应任务的恢复记录；卸载执行中需先等卸载完成。最小化或切到另一游戏不会停止下载。

空间预检会抵扣当前计划中可续传 .tmp 已占的字节，最终仍需校验。等待响应或连续读不到数据达到 60 秒时按网络失败重试；持续传输的大文件没有固定总时长限制。

## 修复 <span id="repair"></span> {#修复}

1. 先关闭游戏。
2. 在“游戏设置 → 安装与维护”或[游戏操作菜单](#游戏操作菜单)选择“修复”，核对确认中的目标游戏。
3. 确认后等待远程清单的 CRC64 检查，重新下载缺失或不匹配文件。
4. 查看结果，失败时使用“查看日志”或按[反馈指南](/cafe-launcher/feedback)导出日志。

![修复确认](../assets/screenshots/dialog-repair.webp)

启动校验只检查存在性与大小，不能替代修复。切换下载源后，已安装游戏应按新下载源修复，使文件与清单一致。

## 启动游戏 <span id="launch-the-game"></span> {#启动游戏}

点击“开始游戏”，启动器先按所选模式校验，再启动本地安装状态指定的入口。默认成功后最小化到托盘，可在“设置 → 常规”修改。

同一游戏的启动或刷新尚未完成时，重复启动请求会被拒绝，包括快捷方式发来的请求。另一款游戏正在下载或修复时，仍可启动本游戏；本游戏有文件任务时先完成或停止并等待收尾。每款游戏分别保存启动后行为。若选择“退出启动器”，而另一游戏仍有文件任务，启动器会提示并改为最小化，让后台任务继续。

| 会话状态 | 含义 |
| --- | --- |
| 游戏启动中 | 等待运行器启动并识别游戏 |
| 游戏运行中 | 已确认游戏进程 |
| 游戏已退出 | 会话结束，有可归属退出码时同时显示 |
| 启动失败 | 未成功进入运行态，恢复主窗口并显示错误 |

没有会话时状态行隐藏，正常退出只更新状态文案。Wine / Proton 不一定有可归属退出码；运行器早退或环境损坏可能导致启动失败。

文件缺失或大小不匹配时，启动前会提示修复：

![启动校验失败](../assets/screenshots/dialog-repair-launch-check.webp)

Linux 依赖[兼容运行环境](/cafe-launcher/settings#兼容运行环境-仅-linux)，macOS 暂不支持启动游戏。

## 游戏操作菜单 <span id="game-menu"></span> {#游戏操作菜单}

游戏就绪时，点击“开始游戏”右侧的菜单入口。左侧主按钮仍直接启动；简略和隐藏状态面板布局都提供此入口。

| 操作 | 用途 |
| --- | --- |
| 检查更新 | 刷新远端游戏版本与主按钮状态 |
| 添加桌面快捷方式 | 创建绑定当前游戏的启动器入口：Windows `.lnk`、Linux `.desktop`、macOS `.command`；仍受对应平台的游戏启动能力限制 |
| 打开游戏目录 | 在文件管理器中打开当前目录 |
| 修复 | 完整 CRC64 检查并补齐文件 |
| 卸载 | 删除整个游戏目录，需确认范围 |

上述管理动作也可从“游戏设置 → 安装与维护”进入。设置有改动时先选择继续编辑，或放弃改动后继续操作。菜单进入修复后，取消或按 Esc 返回原启动控件。

![游戏操作菜单（旧版示意）](../assets/screenshots/game-menu.webp)

这张截图来自旧版菜单，当前入口位于“开始游戏”右侧。

新游戏快捷方式都先进入 Cafe Launcher，并携带明确目标：`--launch-game --game-id blue-archive-jp` 或 `--launch-game --game-id stella-sora-cn`。它们不依赖游戏目录中的 `run.bat`。旧版 Windows 直连脚本快捷方式不会被自动改写；旧的裸 `--launch-game` 参数固定指向蔚蓝档案。未知游戏 ID 会被拒绝，不按当前页面猜测目标。

已有启动器运行时，新快捷方式会把目标传给原实例。遇到确认框、未保存设置或本游戏文件任务时会提示受阻，不会关闭对话框、丢弃草稿或延后自动启动。

## 卸载游戏 <span id="uninstall-the-game"></span> {#卸载游戏}

关闭游戏后，在“游戏设置 → 安装与维护”或游戏操作菜单选择“卸载”，核对目标游戏、完整路径、预计大小，以及是否额外清理受管兼容环境，再确认。

如果确认框出现前切换了游戏，切回原条目后需要重新选择“卸载”。

> [!WARNING]
> 默认删除整个游戏目录，包括游戏自行下载的资源和用户放入的文件，同时清理安装状态、恢复记录与桌面快捷方式。请先备份需要保留的内容。

卸载显示扫描、删除进度与结果，列出无法删除的项目。完成前保持启动器运行，可以最小化。自定义 Prefix 位于游戏目录和所选受管子树之外时保留。

启动器卸载与游戏卸载分别处理，见[卸载与数据](/cafe-launcher/uninstall)。

## 日志查看器 <span id="log-viewer"></span> {#日志查看器}

打开“设置 → 高级 → 查看日志”，按级别浏览、搜索当前与轮转日志。

![日志查看器](../assets/screenshots/log-viewer.webp)

记录分批加载，搜索与级别筛选只作用于已加载内容。需要完整时间范围时，使用[导出日志](/cafe-launcher/feedback#导出日志)。

日志查看器可覆盖在设置上；查看器中的“导出日志”再打开一层，Esc 按层返回并保留设置草稿。卸载失败结果中的“查看日志”会关闭结果表面再进入查看器，关闭后返回首页。

## 系统托盘 <span id="system-tray"></span> {#系统托盘}

关闭行为为“最小化到托盘”时，关闭按钮隐藏窗口，进程继续运行。托盘可显示主窗口、开始游戏、打开设置或彻底退出。

![托盘菜单](../assets/screenshots/system-tray.webp)

游戏启动中或运行中时，托盘启动项显示会话状态。需要确认框或设置页面时会恢复主窗口。再次运行启动器会唤醒已有实例；同一用户数据目录只允许一个实例，Linux 也跨登录会话判定。
